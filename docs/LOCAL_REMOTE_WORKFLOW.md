# 本地开发与远程实验规范

本项目采用“本地开发 → 服务器验证与实验 → 结果回传 → 本地分析”的流程，与 [第一轮开发计划](FIRST_ROUND_DEVELOPMENT_PLAN.md) 配合使用。

目标：每份结果可追溯，本地分析无需重新运行模型。下列目录与入口为开发约定，尚待实现。

## 1. 工作分工

- **本地：** 编写代码、检查数据与配置、分析结果和绘图。
- **服务器：** 加载模型、验证原样恢复、运行 baseline 与干预实验。
- 服务器上的临时修改必须同步回本地，避免两端代码分叉。

## 2. 配置与版本

- **实验配置**保存数据集、样本选择、latent 步数、解码参数、干预参数和随机种子。
- **机器配置**保存数据、checkpoint、输出目录及设备设置；代码中不写死绝对路径，项目内相对路径统一从项目根目录解析。
- 每次实验保存最终生效配置、实际样本 ID、模型与数据标识，以及 dtype、batch size 等运行参数。
- 记录项目和关键依赖的 commit；未提交修改保存可恢复的源码快照，包含新增文件。
- 记录 Python、PyTorch、Transformers、GPU 和 CUDA 环境。正式实验使用固定代码副本，运行期间不覆盖。
- 修改模型、依赖或数值设置后，重新进行小规模验证；固定种子不保证跨环境逐位一致。

## 3. 执行流程

1. **本地准备：** 检查数据读取、答案解析和配置，确定上传版本。
2. **上传：** 同步源码与配置；数据、checkpoint、虚拟环境和历史结果单独管理。
3. **小规模验证：** 用固定样本检查模型加载、推理、干预和结果保存，并完成一次下载与本地分析。
4. **正式实验：** 沿用验证通过的版本，新建独立运行目录，保存日志和任务状态。
5. **结果回传：** 检查完成数量、失败情况和文件校验值，下载结果包。
6. **本地分析：** 保留原始结果，统计与图表另存，并记录分析代码版本。

**正式干预实验前，原样恢复验证必须通过：** 在各 latent 位置将原向量传回后，最终生成结果一致，轨迹与 logits 在设定容差内一致；各干预分支不得污染共享状态。

baseline 与干预实验使用一致的模型、样本、输入和解码配置，结果明确关联对应 baseline。先完成小规模全流程，再扩大实验。

## 4. 结果保存

每次运行使用唯一 `run_id`，不覆盖历史结果。建议目录：

```text
outputs/<run_id>/
├── manifest.json          # 状态、代码版本、模型与数据标识
├── config.resolved.yaml   # 最终配置
├── environment.txt        # 环境与设备
├── samples.json           # 实际样本 ID
├── predictions.jsonl      # 逐条结果
├── summary.json           # 汇总指标与完成数量
├── logs/                  # 运行日志
└── traces/                # 按需保存的轨迹
```

逐条结果至少包含：样本 ID、干预位置与参数、随机种子、baseline 与干预后的生成文本和提取答案、gold answer、两次正确性、解析状态及执行状态。

- 运行状态区分运行中、完成、失败和中断；全部完成并检查通过后才标记完成。
- 恢复运行时避免重复记录；配置变化则新建运行。
- 报告预计、完成、解析失败和执行失败数量。
- 解析失败单独计数，端到端准确率中按未答对处理；执行失败不自动当成模型答错，未完成实验标注为部分结果。
- 干预分别报告错误 → 正确、正确 → 错误及其他答案变化；比例附分子和分母，成对比较仅使用两侧均完成的记录并报告排除数量。
- 保存答案规范化与评测规则版本，确保本地可重算指标。

## 5. 轨迹与回传

- 逐条结果与汇总完整保存；latent 向量和详细 logits 按指定案例保存，策略写入配置。
- 大张量单独存为 CPU 数据，轨迹引用使用运行目录内的相对路径。
- KV cache 默认只用于运行时恢复；checkpoint 不加入日常结果包。
- 回传配置、版本与环境记录、样本列表、结果、日志及选中轨迹；未提交源码附可恢复快照。
- 下载后核对校验值和记录数量。服务器原始结果至少保留到本地校验通过，清理不与同步操作绑定。

## 6. 开发与验收要求

计划提供 `run_baseline.py`、`check_resume.py` 和 `run_interventions.py` 三个入口，统一配置、样本选择与输出格式，并支持少量样本运行。

本地分析程序只读取回传文件，不依赖模型权重或服务器路径。

第一轮验收：固定版本在服务器完成 baseline、原样恢复验证和逐位置干预；结果回传后，本地能够重算指标、查看案例，并识别失败或部分完成任务。
